# QuickNotes Data Model

QuickNotes uses PostgreSQL. IDs are UUIDs generated by PostgreSQL (`gen_random_uuid()`, available in supported modern PostgreSQL releases); all timestamps are stored as `timestamptz` in UTC.

## Entities and relationships

- **users**: one row per account; `id UUID` is the primary key and `email` is unique. A user can own many notes and many tags.
- **notes**: one row per note; `id UUID` is the primary key and `user_id UUID` is a foreign key to `users.id`. `title` is limited to 100 characters; `body` may be empty. `deleted_at` supports soft deletion.
- **tags**: one row per user-defined tag; `id UUID` is the primary key and `user_id UUID` is a foreign key to `users.id`. Tag names are unique per user, not globally.
- **note_tags**: junction table joining notes and tags. Its composite primary key (`note_id`, `tag_id`) prevents duplicate associations; each column is also a foreign key.

The `users` to `notes` relationship is one-to-many: each note has one owner, and one user may own many notes. Notes and tags are many-to-many: a note can have multiple tags and a tag can be applied to multiple notes, represented by `note_tags`. The API verifies that a note and tag belong to the same user before inserting an association.

## PostgreSQL schema

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(320) NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE notes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL,
    title VARCHAR(100) NOT NULL CHECK (char_length(btrim(title)) BETWEEN 1 AND 100),
    body TEXT NOT NULL DEFAULT '',
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    deleted_at TIMESTAMPTZ,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE TABLE tags (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL,
    name VARCHAR(50) NOT NULL CHECK (char_length(btrim(name)) BETWEEN 1 AND 50),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (user_id, name),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);

CREATE TABLE note_tags (
    note_id UUID NOT NULL,
    tag_id UUID NOT NULL,
    assigned_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (note_id, tag_id),
    FOREIGN KEY (note_id) REFERENCES notes(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE
);
```

## Indexes

```sql
CREATE INDEX idx_notes_user_created
    ON notes (user_id, created_at DESC, id DESC)
    WHERE deleted_at IS NULL;

CREATE INDEX idx_note_tags_tag_note
    ON note_tags (tag_id, note_id);
```

The partial `idx_notes_user_created` index accelerates the common query for a user's active notes in newest-first order while excluding soft-deleted rows. The junction-table index supports finding notes associated with a tag; its primary-key index already supports lookups by `note_id`.

## Example queries

List a user's active notes, newest first:

```sql
SELECT id, title, body, created_at, updated_at
FROM notes
WHERE user_id = $1 AND deleted_at IS NULL
ORDER BY created_at DESC, id DESC
LIMIT $2;
```

Read one note and its tag names with a JOIN, while enforcing note ownership:

```sql
SELECT n.id, n.title, n.body, t.id AS tag_id, t.name AS tag_name
FROM notes AS n
LEFT JOIN note_tags AS nt ON nt.note_id = n.id
LEFT JOIN tags AS t ON t.id = nt.tag_id AND t.user_id = n.user_id
WHERE n.id = $1 AND n.user_id = $2 AND n.deleted_at IS NULL;
```

Find active notes that have a specific tag:

```sql
SELECT n.id, n.title, n.created_at
FROM notes AS n
JOIN note_tags AS nt ON nt.note_id = n.id
WHERE n.user_id = $1
  AND nt.tag_id = $2
  AND n.deleted_at IS NULL
ORDER BY n.created_at DESC, n.id DESC;
```

Count active notes per user, including users with no active notes:

```sql
SELECT u.id, u.email, COUNT(n.id) AS active_note_count
FROM users AS u
LEFT JOIN notes AS n ON n.user_id = u.id AND n.deleted_at IS NULL
GROUP BY u.id, u.email;
```

## SQL or NoSQL?

SQL is the better fit because users, notes, tags, and their associations have clear relationships and integrity rules. PostgreSQL provides foreign keys, unique constraints, transactions for updating a note and its tags together, and efficient joins for filtering notes by tag. Note bodies can still use flexible `TEXT` fields; the service does not need a document database to support that flexibility.
